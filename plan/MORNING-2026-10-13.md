## Two cautions from BUZZ, checked against the code

- **Invite admission on a closed relay.** In source, redeeming an invite ends in an owner-signed member-add command (kind 9030), which is one of the two ways the relay's own closed mode admits, and `ops/buzz-relay/member.mjs` checks that the HTTP bridge refuses a non-member on both `/query` and `/events`. **None of this has run against the relay in closed mode**; BUZZ never ran closed mode either.
- **Two different owner keys.** The pilot gate's owner key is P-256 (`packages/owner-key`), signed inside the device. The Buzz app's key is a different kind (secp256k1): a touch there releases the raw key to the calling process, and the text on the Touch ID sheet is whatever that process passed. So a Touch ID in the Buzz app is weaker evidence than an approval in the gate's popup. This is the same "two paths, two keys" point; do not let the demo blur it.
