# Auma Live voice: source investigation and activation plan

Status: SOURCE-ONLY investigation at `2c7aa31979b8` on 2026-10-13. No node, installed runtime, browser, microphone, provider, or model was inspected. The Linux voice code is present but the repository history labels it source-only and not installed; the live failure that prompted this report was the missing `/etc/aukora/auma-live-voice/environment.sha256` pin ([`plan/NORTH-STAR.md:469-477`](NORTH-STAR.md#L469-L477)).

## Answer

Auma Live voice is dormant for two independent reasons:

1. The cloud node has no verified Linux voice runtime or operator pin. The host now catches that absence, reports `voice not installed on this node`, and keeps the rest of the apps plugin alive ([`plugins/aukora-face/apps/src/auma-live/voice-sidecar.ts:125-145`](../plugins/aukora-face/apps/src/auma-live/voice-sidecar.ts#L125-L145)).
2. Even after installing the sidecar, the current voice WebSocket refuses a normal public HTTPS hostname. The harness first checks its authenticated request gate, but `VoiceWebSocketProxy` then separately requires a loopback socket peer, loopback `Host`, and loopback `Origin` ([`plugins/aukora-face/apps/src/index.ts:965-984`](../plugins/aukora-face/apps/src/index.ts#L965-L984), [`plugins/aukora-face/apps/src/auma-live/voice.ts:61-85`](../plugins/aukora-face/apps/src/auma-live/voice.ts#L61-L85), [`plugins/aukora-face/apps/src/auma-live/http.ts:938-973`](../plugins/aukora-face/apps/src/auma-live/http.ts#L938-L973)). Caddy deliberately preserves the public Host and Origin ([`ops/node-spawn/ingress/Caddyfile.template:38-53`](../ops/node-spawn/ingress/Caddyfile.template#L38-L53)). An HTTPS browser can therefore open the microphone but cannot reach the installed sidecar without a code repair.

The browser fallback does not presently rescue microphone input. Browser speech recognition is explicitly off unless `window.AUMA_LIVE_ALLOW_CLOUD_VOICE === true` before the module loads, because Chrome/Safari recognition can send raw microphone audio to their vendor ([`plugins/aukora-face/apps/vendor/auma-live/runtime/app/aumalive.js:1910-1934`](../plugins/aukora-face/apps/vendor/auma-live/runtime/app/aumalive.js#L1910-L1934)). With no sidecar and no opt-in, typed input remains and a local browser TTS voice may speak replies, but speech-to-text does not run ([`plugins/aukora-face/apps/vendor/auma-live/runtime/app/aumalive.js:2354-2376`](../plugins/aukora-face/apps/vendor/auma-live/runtime/app/aumalive.js#L2354-L2376)).

## End-to-end feature

The current Linux path is:

1. The user presses **Start Voice**. The same-origin page asks for `getUserMedia`, echo cancellation, noise suppression, automatic gain and one channel. It refuses an insecure context or missing media API ([`plugins/aukora-face/apps/vendor/auma-live/runtime/app/aumalive.js:1414-1457`](../plugins/aukora-face/apps/vendor/auma-live/runtime/app/aumalive.js#L1414-L1457)). The containing same-origin iframe grants `microphone; autoplay` ([`plugins/aukora-face/apps/src/client/AumaLiveSurface.tsx:36-43`](../plugins/aukora-face/apps/src/client/AumaLiveSurface.tsx#L36-L43)).
2. An AudioWorklet resamples microphone audio to mono PCM16 at 16 kHz in 40 ms frames; its paired player accepts PCM16 at 24 kHz and resamples it to the device ([`plugins/aukora-face/apps/vendor/auma-live/runtime/app/aumalive-audio.js:14-73`](../plugins/aukora-face/apps/vendor/auma-live/runtime/app/aumalive-audio.js#L14-L73), [`plugins/aukora-face/apps/vendor/auma-live/runtime/app/aumalive-audio.js:78-121`](../plugins/aukora-face/apps/vendor/auma-live/runtime/app/aumalive-audio.js#L78-L121)).
3. The browser opens `wss://<page-host>/stock-apps/auma-live/voice?owner=<per-page-token>` under HTTPS, or `ws:` under HTTP ([`plugins/aukora-face/apps/vendor/auma-live/runtime/app/aumalive.js:35-37`](../plugins/aukora-face/apps/vendor/auma-live/runtime/app/aumalive.js#L35-L37), [`plugins/aukora-face/apps/vendor/auma-live/runtime/app/aumalive.js:621-690`](../plugins/aukora-face/apps/vendor/auma-live/runtime/app/aumalive.js#L621-L690)). This is a plugin-owned WebSocket upgrade on the harness HTTP carrier, not the harness `/api/remote.mux` socket. The host relays it to private `ws://127.0.0.1:7512/ws`; port 7512 is configurable but defaults to 7512 ([`plugins/aukora-face/apps/src/auma-live/voice.ts:39-47`](../plugins/aukora-face/apps/src/auma-live/voice.ts#L39-L47), [`plugins/aukora-face/apps/src/auma-live/voice.ts:75-119`](../plugins/aukora-face/apps/src/auma-live/voice.ts#L75-L119), [`plugins/aukora-face/apps/src/index.ts:291-299`](../plugins/aukora-face/apps/src/index.ts#L291-L299)). Port 7512 must remain loopback; it is not a second public/browser port.
4. On Linux, local PCM goes through Silero VAD v6 and `faster-whisper` `tiny.en`, CPU `int8`, with two CPU threads and local-only model loading ([`plugins/aukora-face/apps/vendor/auma-live/source/voice/sidecar.py:121-133`](../plugins/aukora-face/apps/vendor/auma-live/source/voice/sidecar.py#L121-L133), [`plugins/aukora-face/apps/vendor/auma-live/source/voice/sidecar.py:148-171`](../plugins/aukora-face/apps/vendor/auma-live/source/voice/sidecar.py#L148-L171)). One final transcript is returned after the utterance ends ([`plugins/aukora-face/apps/vendor/auma-live/source/voice/sidecar.py:274-369`](../plugins/aukora-face/apps/vendor/auma-live/source/voice/sidecar.py#L274-L369)).
5. The browser sends that text to same-origin `POST /api/auma-live/presence/stream`; this is ordinary HTTP with an SSE response, not audio on port 7512 ([`plugins/aukora-face/apps/vendor/auma-live/runtime/app/aumalive.js:2102-2223`](../plugins/aukora-face/apps/vendor/auma-live/runtime/app/aumalive.js#L2102-L2223)). **Start Voice** first creates a one-hour, in-memory grant for only `turn-text` and `history` to `openrouter.ai`; Stop Voice revokes it and aborts active turns ([`plugins/aukora-face/apps/src/auma-live/http.ts:854-896`](../plugins/aukora-face/apps/src/auma-live/http.ts#L854-L896)).
6. The mind is remote OpenRouter, not the speech sidecar. The default `balanced` mind is `deepseek/deepseek-v4.1-flash`; offered source routes also name `openai/gpt-6-astra`, `anthropic/claude-opus-5.5`, `meta-llama/llama-3.3-70b-instruct`, and `meta/muse-spark-1.3`, all at `https://openrouter.ai/api/v1/chat/completions` and all using the credential reference `OPENROUTER_API_KEY` ([`plugins/aukora-face/apps/src/auma-live/presence.ts:205-268`](../plugins/aukora-face/apps/src/auma-live/presence.ts#L205-L268)). Missing credentials refuse before dispatch ([`plugins/aukora-face/apps/src/auma-live/presence.ts:845-882`](../plugins/aukora-face/apps/src/auma-live/presence.ts#L845-L882)).
7. As reply text streams back, the browser sends sentence/clause chunks over the voice socket. Linux uses local Kokoro-82M int8 ONNX with the default `aurora` blend (`bf_emma` 65%, `af_nicole` 35%), producing PCM16 at 24 kHz ([`plugins/aukora-face/apps/vendor/auma-live/source/voice/sidecar.py:175-214`](../plugins/aukora-face/apps/vendor/auma-live/source/voice/sidecar.py#L175-L214), [`plugins/aukora-face/apps/vendor/auma-live/source/voice/sidecar.py:465-518`](../plugins/aukora-face/apps/vendor/auma-live/source/voice/sidecar.py#L465-L518)). The browser worklet plays it and gates microphone echo/barge-in ([`plugins/aukora-face/apps/vendor/auma-live/runtime/app/aumalive.js:1598-1658`](../plugins/aukora-face/apps/vendor/auma-live/runtime/app/aumalive.js#L1598-L1658)).

This Linux path does **not** use Piper, Pocket-TTS, MLX, a GPU, or a speech API. Pocket-TTS and MLX Whisper belong to the earlier Apple-silicon path. The historical setup used MLX Whisper `base.en` on Apple GPU, Pocket-TTS primary, and Kokoro fallback ([`plugins/aukora-face/apps/vendor/auma-live/voice/sidecar.py:24-30`](../plugins/aukora-face/apps/vendor/auma-live/voice/sidecar.py#L24-L30)).

## What must exist on one Linux node

### Platform and runtime

- Linux `x86_64`, glibc at least 2.28, and exact CPython 3.12.3 are enforced by the installer ([`plugins/aukora-face/apps/vendor/auma-live/source/voice/install.py:159-173`](../plugins/aukora-face/apps/vendor/auma-live/source/voice/install.py#L159-L173), [`plugins/aukora-face/apps/vendor/auma-live/source/voice/install.py:193-203`](../plugins/aukora-face/apps/vendor/auma-live/source/voice/install.py#L193-L203)). Creating the venv also requires the OS `venv` module; the introducing commit says `python3.12-venv` was absent on the pilot.
- `/usr/bin/python3` must hash to `e1efa562c2cc2e35521a5c9c9b9939921001ff8ca9708a13ef15ace68cc2ccd7`, not merely report the right version ([`plugins/aukora-face/apps/src/auma-live/voice-sidecar.ts:154-164`](../plugins/aukora-face/apps/src/auma-live/voice-sidecar.ts#L154-L164)). The installer accepts an operator-supplied baseline hash, but the supervisor hard-codes this one; a different legitimate Ubuntu Python therefore needs code/pin reconciliation before use.
- An absolute operator-selected `voiceRuntimeDirectory` must be configured because releases intentionally omit generated `.venv/` and `models/` bytes ([`plugins/aukora-face/apps/src/auma-live/voice-sidecar.ts:148-153`](../plugins/aukora-face/apps/src/auma-live/voice-sidecar.ts#L148-L153), [`plugins/aukora-face/apps/src/auma-live/voice-sidecar.ts:190-203`](../plugins/aukora-face/apps/src/auma-live/voice-sidecar.ts#L190-L203)). - That runtime must contain `.venv/bin/python`, `sidecar.py`, `environment.json`, `models/`, the pinned Python packages, and the pinned model files. The complete runtime inventory, file modes, symlink targets, OS interpreter, and OS standard-library tree must match `environment.json` before the venv Python executes ([`plugins/aukora-face/apps/vendor/auma-live/source/voice/launch.py:22-61`](../plugins/aukora-face/apps/vendor/auma-live/source/voice/launch.py#L22-L61)).

## Browser-only node

In principle, no desktop app is required. A normal browser on an HTTPS origin is a secure context, the iframe permits microphone/autoplay, Caddy supplies HTTPS certificates and supports WebSocket upgrades, and the page chooses `wss:` automatically ([`ops/node-spawn/ingress/README.md:98-125`](../ops/node-spawn/ingress/README.md#L98-L125)). Audio crosses the public HTTPS connection only through `/stock-apps/auma-live/voice`, then the host makes a new loopback connection to 7512. Port 7512 must not be exposed.

In the current code, however, a browser-only public-host node cannot use the local sidecar: the extra loopback-authority check rejects the public Host preserved by Caddy. Rewriting Host to loopback is not a safe workaround because harness API trust expects the configured public host and same Host/Origin ([`plan/BROWSER-NODE.md:30-37`](BROWSER-NODE.md#L30-L37)). The correct repair is to let the already-authenticated upgrade use the harness's exact trusted public authority, with negative tests for untrusted Host/Origin/cookie and direct exposure. An SSH tunnel whose browser URL is `localhost` fits the current loopback-only check, but that is not the requested public browser product.

## Security answers

- **External reach:** the public voice upgrade first passes the harness connection gate/cookie check ([`plugins/aukora-face/apps/src/index.ts:941-984`](../plugins/aukora-face/apps/src/index.ts#L941-L984)). A structured per-page owner token enforces one active Auma window, but it is a transport lease, not human authentication ([`plugins/aukora-face/apps/src/auma-live/voice.ts:17-20`](../plugins/aukora-face/apps/src/auma-live/voice.ts#L17-L20), [`plugins/aukora-face/apps/vendor/auma-live/runtime/app/aumalive.js:861-900`](../plugins/aukora-face/apps/vendor/auma-live/runtime/app/aumalive.js#L861-L900)).
- **Local reach:** the Python sidecar binds only `127.0.0.1:7512`, but accepts `/health` and `/ws` when Origin is absent. Therefore any process on the node that can reach that loopback port can use the audio/TTS protocol without a credential ([`plugins/aukora-face/apps/vendor/auma-live/source/voice/sidecar.py:42-45`](../plugins/aukora-face/apps/vendor/auma-live/source/voice/sidecar.py#L42-L45), [`plugins/aukora-face/apps/vendor/auma-live/source/voice/sidecar.py:727-795`](../plugins/aukora-face/apps/vendor/auma-live/source/voice/sidecar.py#L727-L795)).
- **Protocol capability:** accepted messages are microphone bytes plus fixed `tts`, `tts_cancel`, `her`, and `reset` controls. There is no command or filename field ([`plugins/aukora-face/apps/vendor/auma-live/source/voice/sidecar.py:763-785`](../plugins/aukora-face/apps/vendor/auma-live/source/voice/sidecar.py#L763-L785)). The supervisor executes one fixed OS-Python launcher; the verified launcher executes one fixed venv Python and `sidecar.py` ([`plugins/aukora-face/apps/src/auma-live/voice-sidecar.ts:148-214`](../plugins/aukora-face/apps/src/auma-live/voice-sidecar.ts#L148-L214), [`plugins/aukora-face/apps/vendor/auma-live/source/voice/launch.py:75-106`](../plugins/aukora-face/apps/vendor/auma-live/source/voice/launch.py#L75-L106)). On STT timeout the sidecar re-executes that same launcher ([`plugins/aukora-face/apps/vendor/auma-live/source/voice/sidecar.py:235-243`](../plugins/aukora-face/apps/vendor/auma-live/source/voice/sidecar.py#L235-L243)).
- **Compromise ceiling:** the child runs as the harness user, not a separate voice user. Environment scrubbing withholds credential-shaped variables, but same-UID file permissions do not stop it reading the harness user's credential and state files; the bundled README says this explicitly ([`plugins/aukora-face/apps/vendor/auma-live/voice/README.md:5-14`](../plugins/aukora-face/apps/vendor/auma-live/voice/README.md#L5-L14)). The browser-node unit has `NoNewPrivileges`, read-only home/system protection, and a narrow writable home subtree, but no private network, syscall/exec filter, CPU quota, or memory maximum ([`ops/node-spawn/browser/node.py:334-361`](../ops/node-spawn/browser/node.py#L334-L361)). A compromised Python dependency could execute programs available to that UID and use its allowed network. Offline environment flags are not containment.
- **Data leaving:** raw audio stays local only on the installed Linux sidecar path. Its transcript plus authorized conversation history goes to OpenRouter for the mind. If the owner explicitly enables browser cloud recognition, raw microphone audio can instead go to the browser vendor. Browser fallback TTS filters to `localService === true`, so reply text is not silently sent to a browser TTS vendor ([`plugins/aukora-face/apps/vendor/auma-live/runtime/app/aumalive.js:1852-1873`](../plugins/aukora-face/apps/vendor/auma-live/runtime/app/aumalive.js#L1852-L1873)).

## Shortest safe activation sequence for one cloud node

1. **Owner decisions — small, owner.** Choose the local Linux path; supply an OpenRouter key and a daily cap; approve whether same-UID execution and unauthenticated node-loopback access are acceptable for the first node, or require a separate voice UID/service and authenticated Unix/socket transport first. Approve the final environment digest and changed plugin/config bytes. No Pocket/Hugging Face paid or gated account is needed for Linux.
2. **Repair public browser voice trust — small code change.** Remove or parameterize the voice proxy's loopback-Host duplicate so it accepts only requests already admitted by the harness's exact public-host cookie/origin gate. Add mutation-tested cases for wrong Host, wrong Origin, missing/invalid auth, direct port access, and accepted public `wss:`. Do not rewrite public Host to localhost and do not expose 7512.
3. **Finish Linux install/activation mechanics — medium code/ops change.** Reconcile the hard-coded `/usr/bin/python3` digest with the installer input; define the final runtime owner/mode so the unprivileged service can traverse the runtime while the supervisor's private-mode check passes; add an operator command that installs only the approved digest at `/etc/aukora/auma-live-voice/environment.sha256`; and wire an absolute `voiceRuntimeDirectory` into the approved node composition. Today the installer prepares bytes but deliberately installs no pin, service, or approval ([`plugins/aukora-face/apps/vendor/auma-live/source/voice/install.py:241-246`](../plugins/aukora-face/apps/vendor/auma-live/source/voice/install.py#L241-L246)).
4. **Prepare and probe the runtime — medium, operator after steps 1-3.** On an offlineable build window, install Python 3.12 venv support; run the pinned installer as root against a new absent runtime; verify every wheel/model hash; run `launch.py ... --verify`, then the CPU `--probe` for VAD/STT/TTS before installing the owner-approved pin. Budget at least 338 MiB of downloads plus unknown unpacked venv/headroom. Confirm at least 50% host and cgroup memory available at first engine load.
5. **Activate through the approved release/config route — small, operator plus owner approval.** Install the exact pin, set `voiceEnabled: true`, `voiceAutoStart: true`, `voicePort: 7512`, and the absolute runtime directory, then use the normal owner-approved plugin-set/release path. Keep 7512 loopback-only. Put `OPENROUTER_API_KEY` in the harness credential store without printing it.
6. **Observe the actual browser behavior — medium, operator and owner.** From the public HTTPS app, Peter presses Start Voice and grants microphone permission. Verify sidecar health, authenticated `wss:` upgrade, 16 kHz audio in, final transcript, one OpenRouter turn, streamed Kokoro 24 kHz audio out, Stop Voice revocation, sidecar-loss fallback with cloud recognition still off, and refusal from an unauthenticated browser and a second/stale voice owner. Record CPU, peak RSS, first-transcript and first-audio latency on that node. Only this step can establish that voice works there.
