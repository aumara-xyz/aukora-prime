## Receipt fields and their limits

All operator prerequisite receipts have `evidence_class: measured` in their first lines and exact SHA bindings in the private manifest. A label, boolean or hash establishes structure/integrity; actual qualification requires the operator's reviewed commands and outputs. Do not manufacture receipts from this schema.

- `runtime_receipt`: `environment_binding_verified: true`, exact `runtime`, and exact `binding` object with `parent_sha256`, `parent_config_sha256`, sorted `base_file_sha256s`, sorted `tokenizer_file_sha256s`, and `engraving_sha256`. This is the pre-run environment envelope, **not** a claim that the model already loaded or that training is qualified. Python/package metadata is checked before imports; actual CUDA/model context checks occur only on approved execution.
- `pricing_receipt`: `currency: USD`, `verified_hourly_rate_usd` and `unavoidable_costs_upper_usd` equal approval fields. Record charge scope, source date and conservative all-in bounds. Include storage as hourly rate or in the other-cost bound without double-counting. Actual billing remains a separate final ledger.
- `disk_receipt`: exact `output_root`, `required_free_bytes >=1073741824`, observed `available_bytes >=required_free_bytes`, `available_inodes >=100`, `measured_at_utc` no more than 900 seconds old. Live worker filesystem stats also check the reserve before loading and between rows. This no-checkpoint allowance does not cover a later training run or establish Mac destination capacity.
- `data_eligibility_receipt`: `approved_for_this_baseline`, `no_private_conversation_ingest`, `no_safety_refused_replay` all true; exact `engraving_sha256`. Data owner supplies the actual review. The manifest also freezes seven complete-row content hashes using the shared canonical JSON row digest. No private/refused case is reconstructed here.
- `supervisor_receipt`: bound `run_id`, `session_id`, `controller_identity`, `provider_deadline_utc`, exact existing `provider_target_sha256`; `armed`, `provider_stop_responsibility_acknowledged`, `independent_stop_qualified`, `partial_export_qualified`, `received_copy_verification_qualified` all true. `qualification_receipt_sha256s` must equal the sorted SHA values of the three manifest `supervisor_qualification_files`.
- The three qualification files are hash-checked measured receipts with `status: QUALIFIED`, matching controller and provider-target hashes, distinct `qualification_kind` values `independent_stop`, `partial_export`, `received_copy_verification`, and nonempty `raw_receipt_files` path/SHA specs. Those raw referenced artifacts are also hash-checked. The operator/H must verify that the raw outputs establish the reported capability. The validator does not perform provider actions or certify that a described control truly ran.

For the provider-target fingerprint, the operator records the canonical hashing scheme and the exact existing instance privately; all controller/qualification receipts must refer to that same target. Raw resource identifiers stay outside the public handoff. A consistent but wrong target would still be unsafe; operator review must compare it to the instance actually controlled.
- The dynamic heartbeat uses the shared core interface: bound run/session/controller/deadline, `armed: true`, timezone timestamp, <=60-second age, regular nonsymlink <=1MiB file. Qualified supervision is outside the worker; a heartbeat cannot kill a blocked CUDA call or stop the instance by itself.

## Measurement and exported result

The baseline matches the saved trial's bf16 base, local tokenizer, no-cache model setting, fixed seed 20260904, Unicode prefix policy and greedy decoder. It validates that the generation prompt's token IDs exactly prefix supervised tokens before masking, sequences fit both 16384 and the declared supported context, and prompt+120 fits. Each target prefix must encode to 1–120 tokens and decode back exactly under the frozen policy. No truncation or hidden fallback occurs. The adapter is explicitly non-trainable and the model eval/inference-only.

Each completed row writes measured loss, strict-prefix recall, token counts, complete-row hash, generated text and row wall time. Encoding and partial results survive ordinary later failures. Raw generated text remains private operator evidence until H's privacy review.

Only seven complete valid rows produce `baseline-receipt.json`: exact `binding`, `metrics`, seven booleans `strict_recall`, seven finite nonnegative `loss`, seven `target_prefix_tokens`, seven row hashes, observed load/encoding/evaluation/wall time and peak CUDA memory. It structurally satisfies the saved training baseline interface, but it cannot qualify training's backward/optimizer/save/reload or authorize that separate experiment. If rows0/1 both pass, the later restoration question must refuse.

Terminal `COMPLETE_BASELINE` is a baseline-protocol status, not a training PASS or a claim of verified cost/shutdown/export. Ordinary errors/refusals/interruption write best-effort outcomes and separate stop request, RESULTS and export manifest; final-write/hash gaps yield returned INCOMPLETE. SIGTERM requests cooperative interruption. Host/process death can prevent finalization entirely; the external operator records that gap. Received-copy SHA verification, final cost ledger and final provider STOPPED remain separate mandatory operator receipts.
