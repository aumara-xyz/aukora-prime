# Pilot runtime readback, 2026-10-10

**Status: RECORDED.** A read-only readback of the running pilot, made twice on 2026-10-10 (05:56 UTC and 06:02 UTC) by an assistant session on the owner's machine, through the SSH loopback forward the desktop owner app already uses. It is an operator-side observation, not an independent attestation. Nothing was changed on the host. The host address, account paths, numeric ids and container ids are deliberately omitted.

## What was run

On the host: `uname`, `/etc/os-release`, `uptime`, a process list by account, `systemctl list-units --type=service`, `ss -ltn` and `openshell --version`. On the owner's machine: the listener and forward for the desktop owner app, and one unauthenticated HTTP request to the forwarded port.

- **Host.** Ubuntu 24.04.4 LTS on x86_64, a Nebius VM (the provider's observability agent was running). Up since 2026-10-05 07:34 UTC.
- **Services.** Eight AUKORA service units were active. Six were running: `aukora-genesis`, `aukora-boundary-gate`, `aukora-openshell-gateway`, `aukora-auma-podman`, `aukora-openviking` and `aukora-relay`. Two one-shot units had completed: `aukora-auma-sandbox` and `aukora-auma-local-deny`.

The runtime process had run since about 2026-10-05 11:18 UTC. Releases `4c24fd0`, `77ee324` and `cdfb55f` were also present on disk and were not running.
- **Separate accounts.** The boundary gate (`gate.mjs serve`) ran under its own gate account. The runtime and its memory service ran under the runtime account. The OpenShell gateway and its container monitors ran under the `auma` account. `openshell-sandbox launch-capability-free` and `openshell-supervisor` ran under user-namespaced sub-ids. The relay ran under its own relay account.
- **OpenShell.** `openshell 0.1.2`.
- **Listeners.** Only SSH listened on a non-loopback address. Every other listener was on loopback, including the two desktop ports and the OpenShell gateway port named in the root README.
- **Desktop owner route.** The desktop owner app on the owner's machine was attached to the runtime through an SSH loopback forward that had been up for about two and a half days. An unauthenticated request to the forwarded port returned HTTP 401. A local owner bridge process had been running for about six days.
- **Staging.** A container named `aukora-staging` on the same host ran a second copy of the same set of processes.

- **Admission.** Whether a normal admitted shell or an accepted bound workspace exists was not checked.
- **Gate package.** The installed gate package version was not read back. It remains Peter-reported as `4c24fd0`.
- **Installed bytes.** No file digests were compared against a release manifest.
- **Owner enrollment.** An owner-supplied screenshot of the desktop window in the same hour showed the Aumlok binding panel as UNBOUND. Real owner enrollment, key custody and human attendance remain unperformed.
- **Prime NEXT.** The pilot runs the Genesis-derived runtime. Prime NEXT is a separate source layer and was not running here.
