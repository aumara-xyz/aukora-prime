Prime transport contracts v1 are frozen by the integration owner. All transport envelopes are closed-field objects and version 1. Only safe integers are transport numbers; currency amounts use decimal strings. UTC timestamps end in Z. operationDigest hashes the domain prefix aukora-prime.operation.v1 followed by NUL and sorted-key compact JSON. A proof is untrusted input until the authority lane verifies material, owner/audience/epoch/expiry/nonce and the exact digest, then durably reserves the consumed grant. The shared validator performs structural validation only; it grants no authority.

MemoryRecord wraps the exact original UTF-8 canonical_bytes with its donor format/canonicalizer and ID. Do not call canonicalJson on the inner original bytes, recanonicalize v0/v1 records or generate salts. Saved and index status are separate. Records never grant authority.

Execution uses OwnedExecutor.execute with operation, consumed_grant, request_id, image_digest, policy_digest, wall_time_ms, max_output_bytes and optional AbortSignal. No argv confinement abstraction or host fallback. Complete means exit zero, fully drained RPC and owned cleanup confirmed absent. Transport failure preserves an observed exit while retaining outcome uncertainty. SDK child launchers remain unavailable until qualified.

Extensions require an integration review and version change for closed fields. Each lane may have local richer interfaces and map them at the transport boundary.

The Opus follow-up tightens validation of these v1 semantics without changing the domain prefix, key order, number encoding, field names or valid digest bytes. `action_type` must be a nonempty string. Configured generic actions retain JSON targets and parameters; their authoritative policy remains in C. The known `shell.bash.foreground` action uses F's exact closed target/parameter fields and pinned bounds. Its environment maps allow only F's guest translations. Receipt `sandbox` is null or F's exact closed UUID/name/identity/image/policy record. Money requires USD decimal strings without leading zeros (zero itself is valid), at most eight fractional digits; existing trailing fractional zeros stay unchanged. UTC timestamp validation checks calendar days and time components, so JavaScript date rollover cannot accept an impossible date. Only receipt `started_at` is nullable. All exported contract field lists are frozen.

`validateContract('ApprovalProof', value)` accepts only structurally signed owner-key or passkey material. Owner-key material is exactly `{kind, request, signature}`, with a 128-character lowercase hex signature; the request has C's seven exact fields and raw hex digests. Passkey assertion material is exactly `{kind, credential_id, client_data_json, authenticator_data, signature, user_handle}`, with canonical nonempty unpadded base64url and C's byte limits (handle may be null). This validates structure, not cryptographic authority. `validateApprovalTemplate(value)` is the separate presentation-only path: owner-key `signature:''`, or passkey `{kind:'passkey'}`. Templates never pass signed-proof validation. B must use the template helper while presenting a challenge.

Actual textual ingress must call `parseStrictJson(text, {maxBytes, maxDepth})` before passing an object to a deserializer. `parseContract(kind, text, options)` combines that parse with schema validation. Defaults and maximums are 8 MiB UTF-8 and 64 nested containers; callers can lower either. The browser-safe parser adapts the AGPL-licensed pinned Kira native-JSON/depth/duplicate scan. It checks decoded duplicate keys at every object depth in the same validated text, including escaped spellings; it rejects lone UTF-16 surrogates in values and keys, negative zero, unsafe integers, and fractional number lexemes that native parsing could silently round to an integer. Exact integer spellings such as `1e0` and `1.0` are accepted. Errors are `ContractValidationError` (a `TypeError`) with `code`/`error_code:'INVALID'`, a stable `reason` and a `path`. No Node polyfills or imports are used in the browser modules. Package browser conditions and the explicit `@aukora-prime/contracts/browser` export select `browser.mjs`.

H owns HTTP request ingress and serving the new `json.mjs` module alongside `shared.mjs`/`browser.mjs`; B owns `response.text()` followed by strict parsing. Already parsed objects contain no duplicate-key evidence: schema validation cannot recover it. C/F private dispatch/cancel/settlement joins remain outside the guest wire schema.

Compatibility changes: formerly accepted malformed values now reject, and proof placeholders require the explicit template helper. `canonicalJson` also rejects cycles, excessive depth, accessors, hidden/symbol fields and nonplain/sparse/extended arrays. Valid v1 values keep the existing compact sorted-key encoding; this is not a JCS or digest-version migration. Memory `canonical_bytes`, donor evidence and source spans remain opaque data; the historical inner JSON is never parsed or recanonicalized by this package, and Kira v0/v1 codecs are untouched.

Run `node packages/contracts/check.mjs --mutations` from the repository root. One scoped check covers three pre-edit frozen operation vectors in Node and browser code, sensitivity of all 17 mutable proposal fields (version changes reject), closed envelopes and known nested shapes, named invalid-input errors, strict ingress, and two exact Kira byte vectors. Eight single-guard/digest removals must fail the assertions, including omission of `canonical_parameters` in either digest implementation. Temporary mutation copies are removed. These checks do not qualify authority, execution, memory storage, a running application or release gates.
