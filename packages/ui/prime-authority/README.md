# Prime owner client

Separate web-only Cordis client `@aukora/prime-authority-ui`, mounted as `prime-owner` in `shell.menu.system` and `shell.surface`. It uses the frozen Layout's exported `ActionButton`, `Panel`, and `SectionHeader` and existing tokens. No frozen face is edited or replaced. `lib/index.js` is deliberately a no-op host.

H serves `/prime/contracts/browser.mjs`, `shared.mjs`, and `json.mjs` through the existing DSH connection gate. The default client POSTs the exact C method envelopes to `/api/prime/authority/{loginChallenge,loginComplete,approvalChallenge,approvalComplete,declineApproval}`, with same-origin credentials, no cache, and refused redirects. Responses use `response.text()` and the shared `parseStrictJson` helper, preserving duplicate-key checks before parsing. Challenge templates use `validateApprovalTemplate`; signed proof validation rejects placeholders. These routes stay `503 UNAVAILABLE` until the host has an explicitly configured verifier. No enrollment, signing key, email login, storage token, reserve, or executor is implemented here.

An optional trusted client service `ctx.primeAuthority` may inject `{authority,contracts,owner_id,loginKinds,ownerSigner,passkeySigner,operation}`. Defaults allow only passkey. Owner-key compatibility requires an explicit allowed kind and injected signer; it never serves as a passkey fallback. The plugin provides `ctx.primeOwnerUi`; H can deliver a validated host proposal with `setOperation(operation)`. A real browser passkey signer additionally requires trusted `passkeyProfile:{profile:'https'|'localhost-pilot-v1',origin,rp_id}`. HTTPS is the default profile; the explicitly selected pilot is exactly `http://localhost:18731` with RP `localhost`. The signer requires the exact browser origin, secure context, Credentials get API, and PublicKeyCredential constructor before requesting an assertion. Missing configuration or any alias is unavailable. No enrollment or authenticator call is performed by source checks. Removing the injected authority disconnects the UI. The default HTTP binding also exposes the same observable controller.

The view renders every frozen proposal field, canonical operation, digest, and fresh review challenge read-only. It waits for C confirmation before displaying an authenticated owner or approved/declined result. A confirmed approval says execution is unconfirmed. Expired, unavailable, credential cancellation, pending, and uncertain responses stay visible; unknown results disable approval retries and require reconciliation. Session tokens and signature material are excluded from presentation.

For `memory.save`, supply the separately prepared immutable four-field capture draft with `setOperation(response.operation, {memoryCapture:response.memory_capture})`, or paired `operation` and `memoryCapture` in the injected binding. The closed draft is `{statement,attributed_to,capture_metadata,evidence_quote}`. Its exact extraction statement, trusted attribution, fixed metadata and full selected source event quotation must be derived independently before awaiting D; never derive expected values from proposed parameters. The copied D checkpoint `6326a4c928a7d14ab7e9ef7a7da626a6a6322d22` helper requires the seven canonical parameters (`capture_sha256`, `idempotency_key_sha256`, `heads`, plus all four draft fields). It compares every literal and all six metadata fields. An optional separate `captureMetadata` sibling must equal the retained draft metadata. Missing, old two/five-field, or mismatched content cannot request a review or sign.

The surface shows the exact escaped statement, attribution, all six metadata fields and full source quotation alongside the capture hash and full operation digest. The quotation may differ from the captured statement; both are visible and digest-bound. The helper requires already-NFC NEW statement and quotation, refuses its declared unsafe controls, invisible fillers and line separators, and preserves permitted scripts, emoji, ZWNJ and ZWJ. It compares and refuses rather than replacing text. Existing Unicode diagnostics run independently on both displayed fields. Historical saved/imported canonical bytes do not pass through NEW-capture admission, and no markup is interpreted. D remains responsible for the private full capture preimage, source evidence and heads under its owner lock; the browser does not reconstruct that hash.

H explicitly joins the browser-safe owner memory workflow after connecting the controller: construct `createUiAdapters({call})` once, use its `authority` in this controller and its `memory` in `createOwnerMemoryWorkflow({controller,memory,contracts})`, then call `controller.setApprovalAction((_view, options) => workflow.approveAndSave(options))`. The owned approval button calls `submitApproval()`. A memory save without this hook is unavailable; there is no automatic save fallback. The workflow must consume this invocation's private `options.approve()` callback and its exact returned proof. Public `controller.approve()` returns null during an owned hook flight; there is no callback cache or raw-approval fallback. Forward the same options to `forgetWorkflow.approveAndForget(options)` for logical forget. H must integrate the matching callback and expanded independent draft into the production bridge before mounting. Clicks coalesce, pending handler replacement refuses, and removing an in-flight handler drops the local owner to fence late approval dispatch. Logout and reconnect hide stale results while the active flight fences new captures. Once the workflow returns a validated, content-free terminal summary, known-unsent saves and completed saves allow a fresh capture. Unknown saves, malformed outcomes and pending authority settlement still require reconciliation. Disposal clears and notifies the owner before removing subscribers, preventing a save that has not yet been sent. The UI renders the detached workflow report with approval, storage, index, citation, receipt and authority settlement separately; a successful C approval alone never reports a save. Missing or mismatched saved record/receipt bindings are uncertain and require reconciliation. Saved-content validation compares the reviewed category, dates, confidence, sensitivity, statement, attribution and exact selected evidence quotation against the original donor canonical bytes and wrapper evidence. The original canonical string remains unchanged.

The hook creates no authenticated transport, trusted source context, enrolled credential or public qualification. H's guarded source factories and protected worker context must remain unmounted/unavailable until independently qualified. Every public worker call must pass `handlePublic`; an internal `handleTrusted` listener cannot be qualified by a capability label. See H's `harness/OWNER-MEMORY-HANDOFF.md` in the canonical source for the separate transport/context composition. B performs no runtime/browser action.

Clean client-only build (freshly built Prime-owned v2 harness and stable identity required):

```sh
node packages/ui/scripts/build-client.mjs --dsh vendor/dsh --prime-root . --only prime-authority --output .runtime/owner-client
```

Without `--only`, the recipe also builds the nine frozen faces in a fresh overlay. First G1 may mount exact donor client bundles without recompiling them. Donor host bundles remain unmounted. The Linux overlay preserves relative PNPM symlinks with `verbatimSymlinks:true`.

The owner receipt is v3 with `owner_build` v2. Its stable build inputs bind the verified `pinned-harness-identity.json` document, fixed compiler files, generated config and independently fixed dependency identities. Raw harness receipt bytes remain historical provenance and never key a downstream build. The recipe verifies the original harness before copying any UI packages, rejects extra hooks and duplicate/escaping workspace seats, and invokes TypeScript and tsdown from their canonical pinned package seats. Historical v1 harnesses and legacy owner receipts refuse; B does not migrate or relabel old outputs.

`verify-owner-build.mjs --ui packages/ui --dsh vendor/dsh --prime-root .` re-derives the stable identity through the same Prime root verifier and checks actual package names, origins, versions, canonical seats, source and outputs. Without `--dsh`, it checks owned source/output and recorded dependency identities only; pinned build inputs remain unverified. `check-owner-build.mjs --dependencies-only --dsh vendor/dsh` runs identity mutations on disposable copies of genuine dependency metadata without compiling or minting a receipt.

Disposable checks:

```sh
node packages/ui/prime-authority/checks/controller.mjs packages/contracts/src/browser.mjs
node packages/ui/prime-authority/checks/render.mjs vendor/dsh packages/contracts/src/browser.mjs
node packages/ui/prime-authority/checks/render-fixture.mjs --dsh vendor/dsh --client-dist .runtime/client-dist --contracts packages/contracts/src --output .runtime/owner-fixture
node packages/ui/prime-authority/checks/serve-fixture.mjs .runtime/owner-fixture
```

The generated fixture loads the actual production client factory and frozen native primitives with pinned React 18.3.1, but injects explicitly synthetic C-shaped responses and assertions. Its permanent banner identifies these as synthetic; no credential is enrolled or requested, no real identity is authenticated, and no operation is executed. It is excluded from the production client bundle. Browser checks use visible controls to verify pending host confirmation, full exact rendering, approval, denial, expiry, and an unknown reply. Stop only the named fixture server after checks.

`render.mjs` separately checks five native-component server-render groups: all exact fields, literal markup escaping, no token/signature leak, disabled duplicate approval, pending login without identity claim, denial, expiry, and an unknown result with retry disabled. This is component render evidence; it does not substitute for browser observation or real owner authentication.

The separate `shell.overlay` capability badge reads guarded GET `/api/prime/capabilities` and shows exact source commit, runtime PID, release digest, pending qualification, and unavailable capabilities. Metadata does not prove loaded memory or successful backend behavior. HTTP owner controls stay disabled while status is pending/unavailable or owner-passkey is unavailable. The badge is centered near the bottom; its expanded panel reserves the shell hot corners. New components follow `../docs/design-contract.md` and composed-browser checks in `../docs/visual-acceptance.json`.
