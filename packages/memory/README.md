# Prime memory source

`createPostgresMemory({pool, authority, contracts, restoreAnchorProvider})` accepts a Prime-owned `pg` Pool, C's real `reserve`, `claimDispatch`, `settleMemory` and optional `markOutcomeUnknown` methods, and the frozen contracts runtime. `pg` 8.16.3 is declared explicitly; real PostgreSQL acceptance remains unperformed in this lane. No sibling repository is loaded by this package.

Capture uses `prepareCaptureBinding(...)`, owner approval of the resulting `memory.save` operation, then `captureAuthorizedRemembered(host, extraction, key, {operation, approval_proof})`. Unsigned capture and tombstone mutators are absent from the public service. Host identity contains distinct `owner_id` and `owner_subject`, plus task ID, privacy, scope, attribution, exact source receipt and source-event bytes. Extraction accepts category, statement, validFrom, observedAt, confidence, sensitivity and links. Historical imported records never pass through a new-note builder.

`prepareCaptureBinding` returns exactly `{target_identity, state_version, canonical_parameters, memory_capture}`. Parameters have exactly five fields: `capture_sha256`, `idempotency_key_sha256`, `heads`, literal `statement` and trusted-host `attributed_to`. The separate `memory_capture` contains the independent literal draft `{statement,attributed_to}` for owner display. The browser-safe `capture-review.mjs` validates this pairing; it does not reconstruct the private capture digest. Statements are exact scalar Unicode, nonblank, at most 4096 UTF-16 units, with LF/TAB allowed and CR, other controls and all bidi controls refused. C's synchronous target callback calls `authorityTargetObservation(op)`, which refuses outside an active owner transaction. `withAuthorityTargetObservation(host, op, fn)` scopes an approval review callback under that lock. The approved save commits a durable prepared intent, reacquires the owner lock and rechecks state, dispatches once, then atomically saves records/events/chain/outbox/idempotency/effect receipt. Three concurrent identical calls on one service coalesce; persisted uncertain intents require reconciliation and never retry automatically.

Approved save returns `{record, receipt, authority_settlement, reconciliation_required}`. `record.storage_status === 'saved'` does not mean indexed or searchable. `drainOutbox(host)` processes only the configured target/generation; `status`, `cite`, `recall` and `repairIndex` retain this distinction. Only after SQL commit does D send its locally derived receipt to C's `settleMemory`. `reconcileEffect(host, operation_id)` resends an identical committed receipt after restart; a prepared intent without an applied receipt reports unresolved and performs no retry.

Import/restore require C-authorized `memory.import`/`memory.restore` operations and parameters `{manifest_sha256, mode, heads, retained_heads}` with mode `kira-import` or `prime-restore`. Target is `{kind:'prime-memory',owner_subject}`; audience is `aukora-prime.memory`. Expected state version is `memoryStateVersion(current database heads)`. Boolean permission callbacks and synthetic CLI bypass flags have no authority.

Ordinary restore always uses `prime-restore`. Its trusted host `restoreAnchorProvider(host)` must supply `{owner_subject,heads}` independently retained outside the guest snapshot; the complete head map must contain a genuinely nonempty chain head. A caller head file is only a cross-check. Anchors, local chain continuity, revision bytes and purge commitments are checked before reserve and again under the write lock. Post-purge imports refuse old IDs, source/evidence references, source forests and quarantined payloads. `memory.import` remains a separate explicitly approved maintenance action and is outside the bridge public allowlist.

`exportSnapshot(host)` emits snapshot v2 profile `normal-redacted/v1`: original historical chain bytes, active canonical record/source bytes, content-free tombstones and opaque digest commitments. It omits forgotten record/source payloads and the imported plaintext source forest. Missing redacted evidence is MISSING, never VERIFIED. Every chain creation, forget and control must reconcile with its projection. A text-bearing historical chain that cannot be redacted without changing its hash is refused explicitly. Independent retained heads are required for an anchored VERIFIED cold result; otherwise the result is UNANCHORED.

`prepareRecordMutationBinding(host,id,{action,at})` prepares approved `memory.forget` or `memory.purge`. `forgetRecord(host,id,{operation,approval_proof})` tombstones visibility and retains canonical payloads. `purgeRecordPayload(...)` removes all active revisions and unique source events for that ID; shared evidence and unresolved save/backup intents refuse before reservation. Parameters bind profile, record ID/revision/original SHA, canonical time and heads. Purge additionally binds a `collateral_scope` with explicit owner imported-forest/full-backup deletion flags, exact closure digests and counts. Other active records remain. Imported source forests and prior full-backup effect results cannot always be separated by record, so their deletion requires this explicit scope.

`prepareBackupBinding`/`exportBackup` require separate `memory.backup` authorization for a full v1 backup. Any tombstone forbids generating or replaying a full backup, including through reconciliation. `eraseOwnerPayloads(host,{at,operation,approval_proof})` requires `memory.erase-owner` bound to `{profile:'prime-active-owner-payloads/v1',manifest_sha256:<current normal export digest>,heads,at}`. It deletes that owner's active payload tables and prior plaintext effect results, retains chain/tombstone/opaque commitments and closed control state, and refuses text-bearing chain payload. Neither purge claims physical media, WAL, prior external backups/copies or C approval-history erasure. No Peter data was imported or erased.

CLI path is `packages/memory/src/cli.mjs`:

- `verify SNAPSHOT OWNER [RETAINED_HEADS_JSON]`
- `export OWNER OUTPUT`
- `restore SNAPSHOT OWNER AUTHORIZATION_JSON [RETAINED_HEADS_JSON]`

Authorization JSON contains `{operation,approval_proof}`. Restore requires injected trusted adapters via `runMemoryCommand(argv,{pool,authority,contracts,host,restoreAnchorProvider})`; standalone restore fails closed. Export uses explicitly supplied `PRIME_MEMORY_DATABASE_URL`. Database migration is an explicit host bootstrap call, not a CLI restore side effect.

Run focused source fixtures with `node --test packages/memory/test/*.test.mjs`. Their disk/restart SQL adapter is SQLite, not PG evidence; the toy authority is private test code with exact registered digests, not production proof verification. `g5-postgres.sh` is restricted to its own marked `/tmp` cluster and must never run against the operator's managed cluster. Operator-managed acceptance uses the separate `test/operator-postgres.mjs` two-phase runner; only H/operator restarts that cluster. Real PG and runtime activation remain UNPERFORMED here.
