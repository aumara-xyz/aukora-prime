# Prime memory source

`createPostgresMemory({pool, authority, contracts, controlRetention, controlRetentionCoordinator})` accepts a Prime-owned `pg` Pool and the frozen contracts runtime. Compatibility paths use C's real `reserve`, `claimDispatch`, `settleMemory` and optional `markOutcomeUnknown`. The configured retained profile instead requires async `reserveRetained`, `claimDispatchRetained` and `settleMemoryRetained`; missing methods refuse `memory:retained-authority-unavailable` without fallback. Control retention defaults to a concrete unavailable reader; restore fails closed without configuration. The owned file reader and separate publisher have explicit constructor, storage and write-coordination requirements in [CONTROL_RETENTION.md](CONTROL_RETENTION.md). `pg` 8.16.3 is declared explicitly; real PostgreSQL acceptance remains unperformed in this lane. No sibling repository is loaded by this package.

The file reader supplies the current retained envelope for the exact owner ID, subject and authorization epoch. Restore binds and rechecks `retention_checkpoint_sha256` and `retention_epoch` in addition to `control_anchor_sha256`. The legacy complete-bundle `restoreAnchorProvider` interface described below remains explicit compatibility; it provides no file-reader storage, pending-marker, epoch or checkpoint qualification. D owns the configured v2 participant/coordinator join and holds one PostgreSQL owner session across its transaction and retention phases. C's pure checks precede the private marker callback; retained PREPARED intent and an updated marker precede dispatch; the final checkpoint precedes retained settlement. See [ATOMIC_RETENTION.md](ATOMIC_RETENTION.md) for exact methods/permits and the pending C staged-generation agreement. Read-only C `80f3e92` is documentation-only and lacks the required implementation. H must supply its existing protected publisher/participant transport. Source tests do not establish actual C/PG/UID/IPC qualification. Retained-profile restore is disabled with `memory:retained-restore-lineage-unqualified`, including preparation.

Capture uses `prepareCaptureBinding(...)`, owner approval of the resulting `memory.save` operation, then `captureAuthorizedRemembered(host, extraction, key, {operation, approval_proof})`. Unsigned capture and tombstone mutators are absent from the public service. Host identity contains distinct `owner_id` and `owner_subject`, plus task ID, privacy, scope, attribution, exact source receipt and source-event bytes. New pilot captures require the six extraction fields and fixed documented metadata: category `fact`, confidence `0.7`, sensitivity `none`, links omitted or empty, owner scope and local privacy. `observedAt` must equal the exact canonical `source.at` and `validFrom` its calendar date. Evidence comes from the selected original source event; evidence/body overrides and nondefault origin refuse. `pilot-capture.mjs` checks these choices before hashing or reservation and returns the unchanged input. Statement and attribution remain explicitly reviewed. Historical imports retain their metadata and original bytes and never pass through this validator or a new-note builder.

`prepareCaptureBinding` returns exactly `{target_identity, state_version, canonical_parameters, memory_capture}`. Parameters have exactly five fields: `capture_sha256`, `idempotency_key_sha256`, `heads`, literal `statement` and trusted-host `attributed_to`. The separate `memory_capture` contains the independent literal draft `{statement,attributed_to}` for owner display. The browser-safe `capture-review.mjs` validates this pairing; it does not reconstruct the private capture digest. Statements are exact scalar Unicode, nonblank, at most 4096 UTF-16 units, with LF/TAB allowed and CR, other controls and all bidi controls refused. C's synchronous target callback calls `authorityTargetObservation(op)`, which refuses outside an active owner transaction. `withAuthorityTargetObservation(host, op, fn)` scopes an approval review callback under that lock. The approved save commits a durable prepared intent, rechecks state in the next transaction, dispatches once, then atomically saves records/events/chain/outbox/idempotency/effect receipt. In the configured retained profile, one dedicated PoolClient and its actual session advisory lock remain held across these transactions, file checkpoints and C settlement; private phase callbacks inspect that same backend's granted owner lock. Three concurrent identical calls on one service coalesce; persisted uncertain intents require reconciliation and never retry automatically.

Browser-safe `capturePresentationWarnings(statement)` in `capture-presentation.mjs` supplies bounded hints for Unicode format controls, selected Greek/Cyrillic letters resembling ASCII, and mixed Latin/Greek/Cyrillic words. Each hint identifies unchanged UTF-16 indexes and code points. The list is incomplete, legitimate languages remain accepted, and no string is normalized or replaced. NFC does not remove lookalike risks. UI consumers must show these hints beside the escaped exact paired draft; this source package does not establish that the running owner UI displays them.

Approved save returns `{record, receipt, authority_settlement, reconciliation_required}`. `record.storage_status === 'saved'` does not mean indexed or searchable. `drainOutbox(host)` processes only the configured target/generation; `status`, `cite`, `recall` and `repairIndex` retain this distinction. After SQL commit, compatibility paths send the locally derived receipt to C's `settleMemory`. The configured retained profile first publishes and reads back the complete final checkpoint, then uses `settleMemoryRetained` and the private participant's actual-effect permit. `reconcileEffect(host, operation_id)` resends an identical committed receipt after restart; retained reconciliation first verifies/completes the factual checkpoint under a held owner session. A prepared intent without an applied receipt reports unresolved and performs no retry.

Import/restore require C-authorized `memory.import`/`memory.restore` operations. Legacy data import parameters are `{manifest_sha256, mode, heads, retained_heads}` with mode `kira-import`. Restore additionally requires `control_anchor_sha256` and mode `prime-restore`; `prepareRestoreBinding(host,snapshot)` prepares the exact operation parameters and current target state. Target is `{kind:'prime-memory',owner_subject}`; audience is `aukora-prime.memory`. Expected state version is `memoryStateVersion(current database heads)`. Boolean permission callbacks and synthetic CLI bypass flags have no authority.

Configured retained-profile restore preparation and execution refuse `memory:retained-restore-lineage-unqualified`; C/D self-lineage remains unqualified. The following restore behavior describes explicit compatibility source paths only. Ordinary restore always uses `prime-restore`. Its trusted host `restoreAnchorProvider(host)` must supply the latest independently retained complete `aukora-prime-memory-control-state/v1` bundle for the exact owner ID and subject. Heads-only anchors and data snapshots refuse. The complete head map must contain a genuinely nonempty chain head. A caller head file is only a cross-check. The host must protect the current retention pointer independently of the recoverable database and incoming snapshot; an old self-consistent backup is not evidence that it is current. Restore binds and rechecks the control digest, validates local continuity/revisions, and unions retained and local durable rows under the owner lock. Conflicts, foreign grant/request bindings and omitted control projections refuse. Purges, tombstones, redactions, capture idempotency rows, unresolved intents, committed effect receipts and content-free replay fences survive. Unresolved intent has no applied result and never automatically retries. Post-purge imports refuse old IDs, source/evidence references, source forests and quarantined payloads. Prime-origin or normal v2 data exports cannot bypass this through `memory.import`, which remains a separate explicitly approved legacy maintenance action outside the public bridge allowlist.

`exportControlState(host)` is a sensitive trusted-host retention seam, outside the guest/public bridge. The portable bundle has exactly `{schema,owner_subject,owner_id,heads,tables,control_sha256}`. All eight durable tables are required: `purges`, `requests`, `intents`, `effects`, `tombstones`, `controls`, `redactions`, `replay_fences`. Original bytea fields use `{bytes_base64,sha256}` and remain byte-identical; the domain-separated outer hash establishes self-consistency, while the independent current provider establishes trust. Saved operation/receipt bytes can retain statement text, canonical record bytes and approved parameters. Independently protect and retain this control backup separately from ordinary record snapshots. Its exported copies are not erased by a later local forget/purge. Data export and cold citation verification remain record-history operations, not authoritative control-backup verification.

`exportSnapshot(host)` emits snapshot v2 profile `normal-redacted/v1`: original historical chain bytes, active canonical record/source bytes, content-free tombstones and opaque digest commitments. It omits forgotten record/source payloads and the imported plaintext source forest. Missing redacted evidence is MISSING, never VERIFIED. Every chain creation, forget and control must reconcile with its projection. A text-bearing historical chain that cannot be redacted without changing its hash is refused explicitly. Independent retained heads are required for an anchored VERIFIED cold result; otherwise the result is UNANCHORED.

`prepareRecordMutationBinding(host,id,{action,at})` prepares approved `memory.forget` or `memory.purge`. `forgetRecord(host,id,{operation,approval_proof})` tombstones visibility and retains canonical payloads. `purgeRecordPayload(...)` removes all active revisions and unique source events for that ID; shared evidence and unresolved save/backup intents refuse before reservation. Parameters bind profile, record ID/revision/original SHA, canonical time, heads, literal statement and attribution. Purge additionally binds a `collateral_scope` with explicit owner imported-forest/full-backup deletion flags, exact closure digests and counts. Other active records remain. Imported source forests and prior full-backup effect results cannot always be separated by record, so their deletion requires this explicit scope. Capture idempotency rows remain content-free fences; plaintext-bearing deleted intent/effect rows are replaced with `payload-purged` replay fences binding operation/grant/request digests. Reconciliation and replay of these removed results refuse. Unresolved save keys also refuse a new operation/grant until factual reconciliation resolves their intent.

For the approved bridge surface, both mutators accept trusted-host `include_receipt:true` and then return `{result,receipt,authority_settlement,reconciliation_required,...}` using the actual committed D receipt and C's settlement response. Flat result output remains the default. Keep review and reserve/claim target observation inside `withAuthorityTargetObservation`; display D's independently prepared record summary and the exact bound record SHA/time/profile. A public forget route must authenticate the owner and task and map only these approved methods. Raw tombstone/delete routes remain forbidden. This D package does not activate or edit the C/bridge/UI route.

`prepareBackupBinding`/`exportBackup` require separate `memory.backup` authorization for a full v1 backup. Any tombstone forbids generating or replaying a full backup, including through reconciliation. `eraseOwnerPayloads(host,{at,operation,approval_proof})` requires `memory.erase-owner` bound to `{profile:'prime-active-owner-payloads/v1',manifest_sha256:<current normal export digest>,heads,at}`. It refuses unresolved intents and text-bearing chain payload, removes active payloads and prior plaintext effect results, and preserves chain/tombstone/opaque commitments, purge registry, idempotency and replay fences. Logical forget retains canonical payloads; local payload purge does not erase C's approval/operation history, prior external record/control backups and copies, WAL or physical media. No Peter data was imported or erased.

CLI path is `packages/memory/src/cli.mjs`:

- `verify SNAPSHOT OWNER [RETAINED_HEADS_JSON]`
- `export OWNER OUTPUT`
- `restore SNAPSHOT OWNER AUTHORIZATION_JSON [RETAINED_HEADS_JSON]`

Authorization JSON contains `{operation,approval_proof}`. Restore requires injected trusted adapters via `runMemoryCommand(argv,{pool,authority,contracts,host,controlRetention,controlRetentionCoordinator})`, or the explicit legacy provider; standalone restore fails closed, and the configured retained profile refuses unqualified restore. Export uses explicitly supplied `PRIME_MEMORY_DATABASE_URL`. Database migration is an explicit host bootstrap call, not a CLI restore side effect.

Run focused source fixtures with `node --test packages/memory/test/*.test.mjs`. Their disk/restart SQL adapter is SQLite, not PG evidence; the toy authority is private test code with exact registered digests, not production proof verification. `g5-postgres.sh` is restricted to its own marked `/tmp` cluster and must never run against the operator's managed cluster. Operator-managed acceptance uses `test/operator-postgres.mjs plan|prepare|verify|cleanup-plan CONFIG_JSON STATE_JSON`. The exclusive PG operator creates/drops the exact planned marked schemas and restarts between prepare and verify; the memory role only checks markers and owns its test tables. No database CREATE/TEMP or schema ownership is requested. The operator reports real PG storage-only acceptance with a toy authority in `pg-storage-receipt.json`; this does not prove the C/D IPC join or whole-product G5. Runtime activation remains unperformed.

`test/worker-postgres-fixture.mjs` supplies bounded pool/schema/state/receipt fixtures for the next genuine C/D private-worker PG join. Bridge owns real C proofs, worker/controller configuration and IPC; H owns protected staging/UID/process qualification; the exclusive operator owns PG lifecycle and schema administration. D's helper contains no authenticator keys, authority stand-in, worker activation or schema create/drop. Its supplied C settlement binding is compared with D's committed receipt and explicitly not independently verified as C authority.
