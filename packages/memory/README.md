# Prime memory source

`createPostgresMemory({pool, authority, contracts})` accepts a Prime-owned `pg` Pool, C's real `reserve`, `claimDispatch`, `settleMemory` and optional `markOutcomeUnknown` methods, and the frozen contracts runtime. `pg` 8.16.3 is declared explicitly; dependency installation and real PostgreSQL acceptance remain unperformed in this lane. No sibling repository is loaded by this package.

Ordinary unsigned capture uses `captureRemembered(host, extraction, idempotencyKey)`. Approved capture uses `prepareCaptureBinding(...)`, owner approval of the resulting `memory.save` operation, then `captureAuthorizedRemembered(host, extraction, key, {operation, approval_proof})`. Host identity contains distinct `owner_id` and `owner_subject`, plus task ID, privacy, scope, attribution, exact source receipt and source-event bytes. Extraction accepts category, statement, validFrom, observedAt, confidence, sensitivity and links. Historical imported records never pass through a new-note builder.

`prepareCaptureBinding` returns `{target_identity, state_version, canonical_parameters}`. Parameters bind `capture_sha256`, `idempotency_key_sha256` and exact current chain heads. C's synchronous target callback calls `authorityTargetObservation(op)`, which refuses outside an active owner transaction. `withAuthorityTargetObservation(host, op, fn)` scopes an approval review callback under that lock. The approved save commits a durable prepared intent, reacquires the owner lock and rechecks state, dispatches once, then atomically saves records/events/chain/outbox/idempotency/effect receipt. Races or crashes retain the request identity and require reconciliation; grants are never unconsumed or automatically replayed.

Approved save returns `{record, receipt, authority_settlement, reconciliation_required}`. `record.storage_status === 'saved'` does not mean indexed or searchable. `drainOutbox(host)` processes only the configured target/generation; `status`, `cite`, `recall` and `repairIndex` retain this distinction. Only after SQL commit does D send its locally derived receipt to C's `settleMemory`. `reconcileEffect(host, operation_id)` resends an identical committed receipt after restart; a prepared intent without an applied receipt reports unresolved and performs no retry.

Import/restore require C-authorized `memory.import`/`memory.restore` operations and parameters `{manifest_sha256, mode, heads, retained_heads}` with mode `kira-import` or `prime-restore`. Target is `{kind:'prime-memory',owner_subject}`; audience is `aukora-prime.memory`. Expected state version is `memoryStateVersion(current database heads)`. Boolean permission callbacks and synthetic CLI bypass flags have no authority.

`exportSnapshot(host)` emits snapshot v2 profile `normal-redacted/v1`: original historical chain bytes, active canonical record/source bytes, content-free tombstones and opaque digest commitments. It omits forgotten record/source payloads and the imported plaintext source forest. Missing redacted evidence is MISSING, never VERIFIED. Every chain creation, forget and control must reconcile with its projection. A text-bearing historical chain that cannot be redacted without changing its hash is refused explicitly. Independent retained heads are required for an anchored VERIFIED cold result; otherwise the result is UNANCHORED.

`tombstoneRecord` changes visibility and retains the original active-table payload. `prepareBackupBinding`/`exportBackup` require separate `memory.backup` authorization for a full v1 backup. `eraseOwnerPayloads(host,{at,operation,approval_proof})` requires `memory.erase-owner` bound to `{profile:'prime-active-owner-payloads/v1',manifest_sha256:<current normal export digest>,heads,at}`. It deletes that owner's active payload tables and prior plaintext effect results, retains chain/tombstone/opaque commitments and closed control state, and refuses text-bearing chain payload. It does not erase WAL, backups, snapshots, media or external copies. No Peter data was imported or erased.

CLI path is `packages/memory/src/cli.mjs`:

- `verify SNAPSHOT OWNER [RETAINED_HEADS_JSON]`
- `export OWNER OUTPUT`
- `restore SNAPSHOT OWNER AUTHORIZATION_JSON [RETAINED_HEADS_JSON]`

Authorization JSON contains `{operation,approval_proof}`. Restore requires an injected trusted C adapter via `runMemoryCommand(argv,{pool,authority,contracts,host})`; standalone restore fails closed. Export uses explicitly supplied `PRIME_MEMORY_DATABASE_URL`. Database migration is an explicit host bootstrap call, not a CLI restore side effect.

Run the focused source fixture with `node --test packages/memory/test/memory.test.mjs`. Its disk/restart SQL adapter is SQLite, not PG evidence; the toy authority is private test code with exact registered digests, not production proof verification. G5 is `PRIME_MEMORY_POSTGRES_BINDIR=<existing approved official bin directory> sh packages/memory/test/g5-postgres.sh`, after the declared pg driver is materialized. It starts only a disposable marked cluster with a private Unix socket and no TCP listener. No PostgreSQL binary/driver was available here; that arm remains explicitly UNPERFORMED.
