## Concrete setup permission proposal

After source review, request permission on this existing host only to install the four exact official packages and start one private Docker daemon; allocate one non-login executor UID distinct from host ubuntu1000, root and supervisor65534; create root-private control/data directories, root-only Unix Docker socket and dedicated resource slice; pull the four recorded immutable image inputs; build one local workload image; generate one local mTLS/JWT bundle in a dedicated control environment; start one root-trusted control gateway using the pinned image with host networking and exact loopback-only listeners, then run one approved inert foreground call and scoped deletion/readback. The gateway's default CMD must be cleared so it cannot override loopback TOML. Gateway root trust and its approved control/socket mounts are explicit; workload/supervisor receive no Docker socket, host workspace or host credentials. No Docker-group grant to ubuntu, public port, model/provider key, firewall change, additional VM, publishing or unrelated process stop is included. No setup command in this document has run.

Use real v2 gateway fields: `tls.{cert_path,key_path,client_ca_path}`, `mtls_auth.enabled=true`, `auth.allow_unauthenticated_users=false`, `gateway_jwt.{signing_key_path,public_key_path,kid_path}`, and complete `guest_tls_{ca,cert,key}`. Native loopback or host-networked gateway is required; bridged loopback plus published ports is ineffective. Supervisor is **65534:65534**, readonly root, host network; guest is **1000:1000**, network none, caps dropped/no-new-privileges. The boundary socket is deliberately **0666 with mTLS/session authentication**, not a 0600 ACL. Supervisor control credentials are separate from the guest boundary server key. Upstream `generate-certs` also copies client material to XDG state; use dedicated control HOME/XDG, never private-PEM-printing dry-run. Its local client cert is shared, not proof of distinct operator/supervisor principals. ## Proposed

1. Trusted composition produces a **proposal**. A reviewed child-policy adapter compares fully effective candidate against an owner-approved maximum, then creates the exact frozen operation for fresh C approval. Agent-controlled intercepts never authorize execution. No envelope renaming or automatic grant follows from composition or a prover pass.
2. Preserve F JSON `policy_digest` and upstream `deterministic_policy_hash` as distinct identities. F now reads raw `GetSandboxConfig` and checks the entire fixed policy/source, zero global version, exactly four unset settings, empty middleware/providers, fail_closed validation, extensions disabled, fresh policy history1 and exact installed admission tuple. Its restricted upstream protobuf/hash port preserves the distinct policy/config/provider identities; durable uint64 values are decimal strings. Bind actual runtime observations to the trusted accepted profile before mounting. First pilot requires no global override/providers/middleware and exact admitted tuple. UInt64 revisions are equality tokens, never lossy numbers. [Effective config](https://github.com/NVIDIA/OpenShell/blob/6648bd0c290efbc41ba131ee9831ee45cd431f94/proto/sandbox.proto#L404), [global replacement](https://github.com/NVIDIA/OpenShell/blob/6648bd0c290efbc41ba131ee9831ee45cd431f94/crates/openshell-server/src/grpc/policy.rs#L1786), [hash encoding](https://github.com/NVIDIA/OpenShell/blob/6648bd0c290efbc41ba131ee9831ee45cd431f94/crates/openshell-core/src/policy_identity.rs#L155).
3. F refuses drift immediately before exec and preserves unknown after a changed/unavailable post-drain readback. A pending verification fence is durable before dispatch and clears only after a verified post-drain save, so process death cannot skip the final check. Continuous generation monitoring/cancellation remains Proposed. Readback is not an atomic expected-policy fence on ExecSandbox. Keep concurrent policy administration disabled for the bounded first probe; an atomic or otherwise qualified generation join is still needed before general activation. Fresh widening requires exact new owner approval. Static narrowing requires fresh owned recreation; do not claim hot reload narrowed an existing child.
4. Coordinate H/C fixes for indistinguishable **synthetic timeout124** and the lifecycle/resource/effective-policy joins. Gateway sends typed124 plus RPCsuccess on timeout while leaving the launch unresolved. A genuine exit124 looks identical. Do not settle either as known command failure without additional trusted terminal provenance; keep conservative unknown evidence and permanent fences. [Timeout source](https://github.com/NVIDIA/OpenShell/blob/6648bd0c290efbc41ba131ee9831ee45cd431f94/crates/openshell-server/src/grpc/sandbox.rs#L3420). F now keeps raw124 separately, retains command exit null, and records successful RPC drain as complete with factual OUTCOME_UNKNOWN. C1be5 rejects complete/null receipts; until its narrow validator allowance is reviewed, F preserves a pending outbox and blocks admission rather than falsifying RPC facts. Frozen envelopes and digest domains are unchanged.
5. Add independent durable scoped cleanup supervision. Gateway/client death is not termination; graceful gateway stop can preserve running intent for restart. JWT connection expiry and disconnect recovery are conditional mechanisms, not a per-call TTL or cleanup proof. Never replay an uncertain create/exec or clear an unknown fence. OCSF is lossy structured telemetry, not signed immutable evidence; use typed bound control-plane facts and F/C durable receipts for settlement.

Pinned containment CLI is real: `openshell-prover check candidate.yaml --boundary boundary.yaml --output json --timeout 10s`. Accept only `within_boundary` with all required coverage; unsupported/inconclusive/error refuse. It models filesystem, L4 TCP, REST, process identity and Landlock compatibility, not resource enforcement or credential/global overlays. Arbitrary descendant paths/workdirs/symlinks and advanced protocol/credential rules can be unsupported. It does not compose provider rules, apply policy or authorize anything. Gateway proposal-risk analysis is a different check. [Pinned prover](https://github.com/NVIDIA/OpenShell/blob/6648bd0c290efbc41ba131ee9831ee45cd431f94/docs/how-it-works/policies/prover.mdx).

At this pin network/OPA and provider state can change live. Sandbox updates hold process/Landlock fixed and allow only additive filesystem changes; additions take effect after restart, not in running children. Unactivated Pending/Rejected repair has a separate exception. Global policy replaces the sandbox/provider layers, including initial static policy, while existing kernel static restrictions remain startup-bound. [Static validation](https://github.com/NVIDIA/OpenShell/blob/6648bd0c290efbc41ba131ee9831ee45cd431f94/crates/openshell-server/src/grpc/validation.rs#L1023). No generic capability hot reload is proposed.

Credential placeholders are real: revision-bound `openshell:resolve:env:v{revision}_{KEY}` and trusted stable-handle forms keep real secret resolvers supervisor-side. Proxy substitution is endpoint-scoped by host/port/path with generation checks; it does not establish owner consent or binary-scoped credential authority. Positive credential expiry governs resolution, not command termination. Nonsecret configuration can be real env values. This pilot attaches no providers and therefore carries no provider material. [Placeholder generation](https://github.com/NVIDIA/OpenShell/blob/6648bd0c290efbc41ba131ee9831ee45cd431f94/crates/openshell-core/src/secrets.rs#L252), [endpoint binding](https://github.com/NVIDIA/OpenShell/blob/6648bd0c290efbc41ba131ee9831ee45cd431f94/crates/openshell-core/src/provider_credentials.rs#L275).
